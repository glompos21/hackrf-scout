# IQ characterisation: research notes

Raw output of a research run for the idea "label captured IQ (single carrier, bursty/OOK-like, symbol-rate hint, wideband noise)".
These are heuristics measured on **synthetic** signals, not proof and not validated on real HackRF captures.

**Status:** five of the eight planned steps finished. The symbol-rate prototype, the chirp/LoRa/pulsed prototype and the fused classifier did not run (the session limit was hit), so they have no results here. Nothing in this folder is wired into the product.

Code: `prototypes/` (the shared generator `gen.py`, plus amplitude, spectral and partial symbolrate/chirp work). Large data files were left out.


## Codebase integration map

### hook_points

SUMMARY OF WHAT I VERIFIED. Every capture (run and capture commands) goes through one function, _do_captures (hackrf_scout/cli.py:337-355). cmd_run calls it at cli.py:323 inside lock phase "capturing" (319-326); cmd_capture calls it at cli.py:362. There is no other place IQ is recorded for later analysis. Recommended: ONE pure analysis function in a new module (e.g. hackrf_scout/iqfeatures.py, auto-packaged because pyproject.toml:21 lists the single package), called from three places.

HOOK A (primary): inside _do_captures, right after add_capture/mark_captured/commit (cli.py:349-351) and before the _say at 352. Wrap in try/except Exception: log a warn with source="capture" (same style as the failure path at cli.py:346-348) and continue. An analysis bug must never abort a cycle or lose the capture row. Needs: info["path"], info["rate"], info["center_hz"] (returned by capture_signal, capture.py:75), the signals row r (it is a sqlite3.Row with every signals column), and args.lna/vga/amp (cli.py:345). Store change: add_capture (store.py:247-251) returns None today; it must return cursor.lastrowid, or take the result as extra arguments, so the result attaches to the right captures row. Cost: runs while the HackRF is idle but the lock is still held, so it delays the next do_scan (cli.py:314). Note _do_captures's ident parameter is unused today (not needed by the hook).

HOOK B (secondary): a new subcommand, e.g. `hackrf-scout characterise FILE.sigmf-meta... | --signal N | --all`, registered in build_parser next to capture/identify (cli.py:628-651), with its own cmd_ function. It needs no HackRF and must NOT take HardwareLock (_hardware, cli.py:107-125, is only used by scan/run/capture/watch). It is the backfill path for existing captures and the way to re-run after the algorithm changes. It needs sigmf.read_meta, which today returns only sample_rate, center_hz, data_path, datetime (sigmf.py:102-107). It would have to be extended to also return the hackrf_scout:* globals (gains, estimated_bandwidth_hz, baseband_filter_hz, signal_id) and the annotation's freq edges, so a foreign SigMF file with none of those degrades to "no prior" mode. It also rejects non-ci8 (sigmf.py:96-97), which is fine. Pitfalls: (1) common(p) (cli.py:603) defaults --db to scout.db and Store() creates the file, so a loose-file analysis should either require --db or have --no-db; (2) captures.path is stored exactly as built from --capture-dir (cli.py:349, capture.py:46), and the default is the relative "captures" (cli.py:623), so a standalone run from another directory cannot find files; store/resolve an absolute path (the web controller already passes abspath, controller.py:255); (3) matching a meta to a DB signal via hackrf_scout:signal_id is unsafe if captures were moved between databases: also check centre frequency; (4) a second writer while `run` is scanning is fine under WAL, but sqlite3.connect uses the default 5 s busy timeout (store.py:81).

HOOK C (deferred worker, v2): analysis needs no hardware, so it can run while hackrf_sweep scans the next cycle. Constraint: Store.log() is explicitly safe from any thread but nothing else is (store.py:115-118; sqlite3 default check_same_thread), so a worker must hand results to the owning thread through a queue (flushed e.g. in the do_scan loop at cli.py:239-251 or at the next _do_captures), or run the standalone command as a subprocess. Must be joined/cancelled in cmd_run's KeyboardInterrupt/finally path (cli.py:327-334). Only do this if measured too slow on a Pi (see constraints).

NOT recommended:
- capture.py itself (hardware-only, 75 lines; keep analysis out). One tempting shortcut: sigmf.write_meta already makes a full read pass for SHA-512 (sigmf.py:33-38,73), so hashing and feature accumulation could share one pass, but it couples two concerns.
- Scanner/_confirm (scanner.py:276-293): it only sees sweep power, no IQ.
- watch mode live: Watcher.process_slice (watch.py:346-362) holds each raw slice only until power_db returns; bursts are closed later by BurstTracker (watch.py:354-355,184-265), by which time the IQ is gone. Characterising bursts live would need a ring buffer of slices (max_burst_s default 10 s at 6-20 Msps is 120-400 MB), so leave out of v1. Watch --source replay of a capture (cli.py:467-478) already exists but writes signals/bursts and times in 20 ms slices, far too coarse for pulse analysis; it is not a characterise path.
- Web start form: controller.build_scan_args only starts scan/run/watch (controller.py:200-202). The standalone command is CLI-only, which also matches the web layer's read-only design (webapp.py:1-6).

REUSE (verified in code): watch.plan_window(center, rate) (watch.py:102-110) gives the clean window (USABLE=0.75 of the rate, EDGE_GUARD 50 kHz, watch.py:38-39); detect.estimate_floor/detect_signals (detect.py:53,157) already run on IQ-derived spectra in Watcher (watch.py:351-353), and detect_signals' bandwidth rule (edge = max(floor+3, peak-20 dB), detect.py:226) would keep measured bandwidth consistent with the sweep's. watch._nfft_for gives only 128 bins at 2 Msps (15.6 kHz bins) because TARGET_BIN_HZ is 12.5 kHz (watch.py:42,66-67), too coarse for narrowband occupied bandwidth, so use a separate FFT size (1024-4096). watch.file_chunks (watch.py:515-521) silently drops the final partial chunk; write a small shared chunk reader (natural home: sigmf.py) that keeps the tail. Also SliceAnalyzer.power_db subtracts the per-slice mean (watch.py:134), which would also erase a real carrier sitting exactly at DC (see risks).

### data_available

AT HOOK A (inside _do_captures, cli.py:343-353). The loop variable r is the full signals row (SELECT * via store.query_signals, cli.py:338; schema store.py:18-33): id, center_hz, bandwidth_hz (estimated), peak_hz, first_seen, last_seen, first_sweep, hits, max_db, avg_db, last_db, max_snr, last_snr, ident_name/score/source/url, service, ident_json (candidate list; each candidate has modulations, identify.py:163), ident_at, label, notes, captured. capture_signal's return value (capture.py:75): path, meta, rate, seconds, center_hz only. NOT returned but derivable: filter_hz (formula at capture.py:47 and stored in the meta), UTC start (in the meta), gains (args.lna/args.vga/args.amp passed at cli.py:345; these are the same gains the sweep used, since both come from _add_scan_args, cli.py:54-56), file size (expected 2*rate*seconds bytes; the existing test asserts it, test_sigmf.py:67-70). Derived priors worth passing to the analyser: duty = hits/(sweeps - first_sweep + 1) (as in cli.py:404 and query.py:172) and baseline stats from observations (query.py:243). A low duty cycle tells the analyser that a silent capture is more likely "not transmitting in this window" than "no signal". The sweep's max_snr is per 100 kHz bin against the sweep floor and is NOT comparable with an in-capture SNR (README:160 says the same about watch), but a large disagreement is useful evidence that the signal was absent.

CAPTURE GEOMETRY (computed by calling the repo's own pick_sample_rate): rate = ceil(2.5*bw/1 MHz)*1 MHz clamped to 2..20 Msps (capture.py:21-24); baseband filter = min(max(1.5*bw, 1.75 MHz), rate) (capture.py:47). bw 100-200 kHz -> 2 Msps, 1.75 MHz filter, 20 MB per 5 s; bw 1 MHz -> 3 Msps, 30 MB; bw 3.5 MHz -> 9 Msps, 5.25 MHz filter, 90 MB; bw 8 MHz and wider -> 20 Msps, 200 MB (not just 100 MB). Clean span is about 0.75*rate (1.5 MHz at 2 Msps). The recorded hackrf_scout:baseband_filter_hz is the REQUESTED value; hackrf_transfer -b may apply a nearby supported value (libhackrf knowledge, not verifiable in this repo). Captures are centred on the signal's ESTIMATED centre, so the true carrier is usually off-DC by up to tens of kHz: the analyser must find the peak itself, not assume DC. estimated bandwidth_hz is quantised to the sweep bin width: detect.py:241 gives (bins)*bin_hz with a default bin of 100 kHz (cli.py:53), so a 12.5 kHz signal is recorded as >= 100 kHz wide. Measured occupied bandwidth from the IQ is genuinely new information, but keep it separate from signals.bandwidth_hz, which Scanner updates as a running average (scanner.py:214-215).

WHAT THE SigMF META CARRIES (sigmf.py:58-83, capture.py:57-74): global core:datatype ci8, core:sample_rate, core:version 1.2.2, core:recorder, core:hw HackRF, core:description, core:sha512 (data file only, so rewriting the meta never invalidates it), and hackrf_scout:signal_id, estimated_bandwidth_hz, lna_gain_db, vga_gain_db, amp_enabled, baseband_filter_hz. captures[0]: core:sample_start 0, core:frequency (the tune centre), core:datetime (UTC, ms, 'Z'). ONE annotation spanning sample 0..all samples with core:freq_lower_edge/upper_edge = centre +- bw/2 and core:label = ident name or "unidentified". It says nothing about WHEN in the window the signal was on. captures.ts in the DB is local-naive (cli.py:349) while the meta is UTC, so a standalone run should take the time from the meta.

AT HOOK B (standalone): only what read_meta returns today (rate, centre, data_path, datetime, sigmf.py:102-107) until it is extended. The DB row can be found by captures.path (store.py:49) if the path is absolute, then signal context (duty, ident candidates with modulations) joined from signals. For a foreign SigMF file there is no prior: bandwidth hint, gains and signal id are absent and must be optional inputs.

AT HOOK C / watch: only Burst objects (centre, bandwidth, peak, SNR, onset, duration, slices; watch.py:142-152) and per-slice power; no IQ survives (see hook_points).

The ident candidates' modulations hint (cli.py:414, app.js:806) is available at both hooks. Show it NEXT TO any IQ label, but never use it to adjust the label or confidence; that would turn two weak guesses into false agreement.

### storage_options

Constraint that shapes all options: Store has NO migration mechanism. SCHEMA is CREATE TABLE IF NOT EXISTS run on every open (store.py:16-75,85); a grep for ALTER/user_version/migrat finds nothing (the only PRAGMA table_info is the read-only browser, query.py:422). Under the project's no-backward-compatibility rule, schema changes are made directly in SCHEMA. Consequence to document: an existing scout.db keeps the old captures table, so a new INSERT fails with sqlite3.OperationalError ("no column named ..."). main() only catches RuntimeError and KeyboardInterrupt (cli.py:731-736), so users get a traceback after the first capture (the capture file is written but the signal is never marked captured, so the next run re-records it). A CREATE-IF-NOT-EXISTS table, by contrast, appears in an old DB automatically. An optional refusal guard (not compat code) is a Store.__init__ check of PRAGMA table_info(captures) that raises RuntimeError("scout.db is from an older version: move it aside").

(a) NEW COLUMNS ON captures. Suggested: label TEXT, confidence REAL (or a word), features_json TEXT, analysis_version INTEGER, analysed_at TEXT; typed columns only for what you will show or sort on, everything else in the JSON. Pros: captures are 1:1 with analysis (see (d)), so it is the most direct schema change; read-only web needs NO query-layer change for the raw data: list_captures/_simple_list (query.py:341-355) and browse_table (query.py:419-433) are SELECT * and signal_detail does SELECT * FROM captures (query.py:242), so the new keys flow into /api/captures, the Data tab and d["captures"] automatically; table whitelist TABLES (query.py:24), status counts (query.py:153) and tests that pin the table set (test_web.py:292) or the counts dict (test_web.py:833) stay unchanged. Re-analysis is an UPDATE keyed by capture id. Cons: breaks old DBs on the write path (above); features_json arrives as a raw string, so signal_detail should parse it like ident_json (query.py:228-234, try/except ValueError) and not expose the string; no history across algorithm versions (overwrite, with analysis_version recorded).

(b) NEW TABLE capture_features(capture_id PK REFERENCES captures ON DELETE CASCADE, version, analysed_at, label, confidence, features_json). Pros: old DBs get the table automatically with no migration; can hold several algorithm versions if the PK is (capture_id, version); keeps captures lean; also lets you record "analysis failed/skipped" separately. Cons: more touch points in the read-only layer: add to TABLES (query.py:24, else the Data tab cannot show it), the counts tuple (query.py:153), a JOIN in signal_detail (query.py:242) and a custom query in list_captures (query.py:354-355; _simple_list is generic), plus test updates (test_web.py:292,833). A read-only web process pointed at a stale DB that no CLI has opened with the new schema would hit "no such table" in signal_detail, so it needs the existing _has_table guard (query.py:76,343,440).

(c) WRITE INTO THE .sigmf-meta (a second annotation or hackrf_scout:* keys in global). Pros: the result travels with the file, survives losing the DB, and SigMF tools can show it; per-burst annotations (sample_start/sample_count, SigMF's native strength) could mark where the bursts are for inspectrum-style tools. Cons: sigmf.py has no updater (write_meta rewrites everything, sigmf.py:85), so a read-modify-write with atomic tmp+os.replace is needed (pattern at controller.py:131-135); the web layer cannot use it: query.py touches only SQLite, the capture dir is not known to it, IQ and meta files are deliberately not served (README:105), and meta JSON is not queryable or sortable. Rewritten annotation keys must still pass the reference validator that test_sigmf.py:118-130 runs when the sigmf package is installed. Use as a MIRROR of (a), not as the only store.

(d) SIGNALS-LEVEL SUMMARY (columns on signals). Pros: filter/sort by label in the main list (needs LIST_COLS query.py:35-38, SIGNAL_SORTS query.py:28-31, signal_where query.py:105-140, EXPORT_COLS query.py:33 and cli.py:425-426, test updates). Cons: today it is redundant: _do_captures only captures signals with captured=0 and then marks them (cli.py:339,350; store.py:244), so each signal has at most one capture and a summary would equal that capture's result; duplication breeds inconsistency the day recapture exists; and it puts the label in the main table beside ident_name where over-trust is worst. Scanner.update_signal and insert_signal use explicit column lists (store.py:151-167), so extra columns would not be clobbered, but that is the only upside. Better: derive it at query time, no storage: a helper like _burst_counts (query.py:176-180) that fetches the latest capture label per signal id and is attached in list_signals (query.py:214-215), giving a read-only column without duplicating data.

RECOMMENDATION: (a) as the source of truth, with the compact schema above, plus (c) as an optional, later mirror into the meta; derive any signals-list column at query time per (d) instead of storing it. Rationale: fewest touch points, zero query.py changes for the first working version, matches the "edit SCHEMA directly" convention, and the 1:1 capture/analysis relationship makes a second table premature. Choose (b) instead if you want old databases to keep working without refusing, or want multi-version history: it costs query.py + test changes. Whatever is chosen: store features as plain Python float/int/None (np.float32/np.int64 are not json.dumps-able, and NaN/inf would be written as non-standard JSON and are not cleaned inside JSON strings by query._clean, query.py:63-68), and store analysis_version so stale labels are recognisable.

### constraints

NUMPY-ONLY / PYTHON 3.9. numpy is the only dependency (pyproject.toml:10-11: Python >=3.9, numpy>=1.21). No scipy kurtosis/welch/find_peaks/decimate and no sklearn; RF-Sentinel-style IsolationForest/SOM parts are out of scope, so keep it rule-based and explainable (also so each label can list its reasons). Use numpy APIs available in 1.21: avoid np.percentile(method=...) (renamed from interpolation= in 1.22), avoid Python 3.10+ syntax (match, X|Y at runtime, dataclass(slots=True), zip(strict=)). Existing modules use `from __future__ import annotations` (e.g. cli.py:3). I could only run on Python 3.13/numpy 2.5.3 here and the repo has no CI (no .github), so 3.9/numpy 1.21 compatibility is UNVERIFIED by me. Accumulate moments in float64 (float32 sums of 4th powers over 50 M samples lose precision) and combine per-chunk partial sums; do not call a one-shot scipy-style kurtosis on the whole file.

STREAMING A 100-200 MB ci8 FILE. Read in fixed chunks (e.g. 2^20 samples = 2 MiB raw) with np.frombuffer(int8) -> float32 interleave, the same conversion SliceAnalyzer uses (watch.py:131-133), and never np.fromfile the whole file (the web form allows capture_seconds up to 60 and capture_max up to 50, controller.py:248-249, i.e. up to 2.4 GB per capture at 20 Msps). My measurements in this container (4 vCPU, Python 3.13, numpy 2.5.3), one 100 MB file (50 Msamples) streamed, each pass in its own process: read+convert only 0.32 s wall, peak RSS 66 MB; envelope power in 0.5 ms windows 0.29 s, 66 MB; Welch PSD nfft=1024 over every segment 1.45 s wall (1.59 CPU-s), 109 MB; Welch on every 8th segment 0.23 s, 71 MB; both passes about 1.6 s. With 128 Ki-sample chunks RSS was 37-42 MB. Treat these as laptop-class numbers. I did NOT measure a Raspberry Pi; plan on it being several times slower (my unmeasured guess is 5-10x, i.e. 10-15 s for a full-PSD pass over 100 MB). Design for a hard budget: time-based window lengths (not sample counts, because rate spans 2-20 Msps), a cap on samples analysed (e.g. the first N seconds contiguous for envelope/burst statistics, which is cheap, plus strided PSD segments), and a second per-sample pass (downconvert, decimate, pulse timing) only over the 'on' regions found by the cheap pass.

RUN-LOOP TIME BUDGET. hackrf_transfer and hackrf_sweep cannot share the radio, and do_scan starts a fresh hackrf_sweep process each cycle (cli.py:151-154), so any analysis executed inline in _do_captures adds directly to the gap between scans. Default cycle: 600 s of scanning (cli.py:617), up to 3 captures (cli.py:620) of 5 s (cli.py:619), so inline analysis at ~1.6 s per 100 MB adds only a few seconds per cycle on a laptop (<1% of the cycle) and perhaps 15-45 s on a Pi class machine (estimate), still small versus 600 s but not negligible for short --scan-seconds (the web allows 5 s, controller.py:246). Pathological settings (long captures, 50 per cycle) need the sample cap. Options: inline with a cap (v1, simplest, deterministic tests); capture all selected signals first and analyse after (no gain, the radio is still idle until the next do_scan); worker thread or subprocess during the next sweep (zero gap, v2; sqlite writes must stay on the owning thread, see hook C; numpy releases the GIL in FFT and array ops but the main thread must still parse sweep lines).

CPU on small machines: avoid O(N log N) FFT over every sample if not needed; Welch with 1024-4096 bins over a subsampled set of segments is enough to find the carrier peak and occupied bandwidth. No nested Python loops over samples; run-length analysis via np.diff/np.flatnonzero on boolean arrays.

SIGNAL-PROCESSING CONSTRAINTS (all from the hardware/capture design):
- 8-bit ADC and uncalibrated levels: use only relative measures (dB above the capture's own noise floor, ratios, fractions), never absolute dBm; report clipping fraction (|v|>=127) and ADC utilisation (rms/127) and abstain when the capture is too quiet (quantisation-dominated, non-Gaussian) or clipped (harmonics, README:187).
- DC spike at the tune centre (watch.py:14-15). Captures are centred on the signal estimate, so signals often sit within ~100 kHz of DC; mask +-3 bins around DC when estimating the peak/floor. A CW exactly at DC is indistinguishable from DC offset by spectrum alone and mean removal (as in watch.py:134) would delete it, so abstain ("carrier at DC bin") instead of guessing. The watch planner avoids this by tuning DC_GUARD_HZ (100 kHz, watch.py:40) away from the band; the capture side could do the same with an offset tune (capture.py:49 and the meta frequency), which is a capture-design change outside this proposal.
- Baseband filter roll-off: only about 75% of the rate is clean (watch.py:38); estimate the noise floor from the outer passband but inside that limit. For wide signals the clean span may contain no off-signal bins at all (bw >= ~13 MHz at 20 Msps, filter = rate, capture.py:47), so SNR cannot be measured: abstain with reason "signal fills the window".
- Estimated bandwidth is >= the sweep bin width (detect.py:241), so use it only as a search-region prior (the SigMF annotation edges are exactly this prior), not as truth.
- The annotation covers the whole file (sigmf.py:77-80): burst/duty features must be measured, not read from the meta.
- A capture can contain only noise (README:186). The analyser should first decide 'is there anything above the floor at all?' and return a first-class 'nothing detected' state; it must not force a spectral label out of noise.

SCHEMA/PROCESS CONSTRAINTS: no migration convention (see storage). SigMF is ci8 only (sigmf.py:96-97). Validate the meta before dividing: read_meta only checks that the keys exist (sigmf.py:99-100), so a sample_rate of 0 or negative from a hand-edited file would hit division errors; raise ValueError (existing style). Only the owning thread may touch the Store connection (store.py:115-118).

### test_approach

EXISTING PATTERNS TO REUSE
- tests/iqgen.py chunks(rate, seconds, slice_samples, bursts, noise, dc, seed) (iqgen.py:12-31) yields ci8 bytes: Gaussian noise (default sigma 6) plus bursts given as (offset_hz, start_s, duration_s, amplitude, deviation_hz). - Build a real SigMF pair as test_watch.py:382-398 does (iqgen chunks written to a .sigmf-data, then sigmf.write_meta(...)); use it to test the analysis function and the standalone command directly, no HackRF.
- Fake hackrf_transfer: three exist. test_sigmf.py:27-37 writes seeded Gaussian noise (sigma 12) to the -r path; test_pipeline.py:209-219 writes os.urandom bytes; test_watch.py:304-327 (FakeIQ) streams iqgen FSK bursts to stdout for `-r -`. WHAT TO TEST
1. Constructed-extreme cases with wide margins (regression tests, not accuracy claims): CW at +30 kHz offset and high SNR -> single-carrier family; FSK bursts of 60 ms every 1 s (the FakeIQ shape) -> bursty with low on-time and constant envelope inside bursts; OOK with ~1 ms pulses at high SNR -> keyed/bursty with amplitude varying inside bursts; band-limited noise raised across the passband -> wideband; plain Gaussian noise -> 'nothing detected' or 'unknown'.
2. Abstention is part of the contract: all-zero file, constant (DC-only) file, clipped square wave, file shorter than one chunk, odd byte count (partial last sample), empty file, noise below ~2 LSB, CW exactly at DC, signal wider than the window -> label 'unknown' with a reason, no exception, no divide-by-zero warning.
3. Metamorphic/invariance tests (deterministic, robust): scaling amplitude by 2 (stay below clipping) leaves the label unchanged; adding a DC offset leaves it unchanged; frequency-shifting the carrier by +-100 kHz leaves it unchanged; swapping I/Q sign only mirrors the spectrum; the result is identical (to ~1e-6 relative) for chunk sizes 4096 samples vs 1 Mi samples, which proves the streaming merge of partial sums is right; same input + same seed -> same output (determinism).
4. Schema/contract tests: label is in the allowed set, confidence in [0,1], reasons non-empty when the label is not 'unknown', analysis_version present, the dict is json.dumps-able (no np.float32/np.int64/NaN leaking), and a result written into the meta still passes the reference sigmf validation when that package is installed (pattern at test_sigmf.py:118-130).
5. Integration: (a) existing test_run_loop_captures_iq (test_pipeline.py:252-273) must also assert one captures row per capture carries a label from the allowed set (including 'unknown') and a non-null analysis_version, and that the log contains the IQ line; (b) with the new fake, run a one-cycle `run` and assert row + log + meta; (c) failure isolation: monkeypatch the analyser to raise and assert the capture row still exists, signals.captured is 1, and the run exits 0 with a warn log (the hook A try/except); (d) standalone `characterise` on a loose meta without DB writes nothing to scout.db (and does not create one), and with --db updates the row; (e) web: add a capture row with features to a make_db-style fixture (test_web.py:35-79 creates none) and assert signal_detail returns parsed features and /api/captures lists the new columns (test_web.py:896 currently asserts total 0); with option (a) the pinned table set (test_web.py:292) and counts (test_web.py:833) stay valid, with option (b) they must be updated.

WHAT NOT TO ASSERT
- Do not assert exact labels or numbers on random data. The pipeline fake writes os.urandom bytes, i.e. UNIFORM int8, not Gaussian; I measured its envelope kurtosis at 2.44 versus 3.25 for Gaussian noise (and 3.27 for the test_sigmf sigma-12 fake), so any rule written as 'kurtosis near 3 means noise' would miscall that fixture. For that fake, assert only invariants (label in the allowed set, 'unknown' permitted).
- No accuracy, precision, recall, or confusion-matrix thresholds from synthetic data; no exact kurtosis or symbol-rate values except in tight constructed cases with generous bounds (for example 'within 10% of 10 kHz for a long, high-SNR, alternating-bit OOK').
- No wall-clock timing assertions (flaky on CI/Pi); verify the streaming bound structurally (small chunk size gives the same result, and the reader never reads the whole file) instead of measuring RSS.
- No assertion that the IQ label agrees with the Artemis modulation hint.
- Do not tune thresholds against iqgen and then claim validity: iqgen validates the code, not real-world behaviour. Keep a small manual evaluation set of REAL captures (known 433.92 MHz OOK sensor, FSK remote, LoRa, Wi-Fi, an empty channel) outside unit tests, and call the feature experimental in the README until it has been run on it.
- Python 3.9 / numpy 1.21 compatibility cannot be shown by these tests alone (no CI; I only ran Python 3.13), so state it as unverified or add a CI matrix.

### risks

1. OVER-TRUST / FALSE CONFIDENCE. The UI already trains users to read "85%" badges as match quality (app.js:303, cli.py:44-46). A second percentage next to it will be read as probability, but a heuristic confidence without a labelled corpus is not calibrated. Use words (low/medium/high), a neutral badge, an explicit "heuristic" tag, and make "unknown" a normal, visible outcome with a reason. Never let the IQ label change ident_name or the Artemis score. A label such as 'wideband noise' also invites misreading as 'nothing there'; a Wi-Fi/LTE/DVB channel is wideband and noise-like but is a signal, so use 'wideband, noise-like' and never claim the signal is noise.

2. ENVELOPE KURTOSIS ALONE DOES NOT DO WHAT THE IDEA ASSUMES (measured with iqgen-style synthetic ci8, 2 Msps, noise sigma 6, amp 40). Kurtosis of |x|: Gaussian noise 3.25, CW plus noise 3.13, constant-envelope FSK plus noise 3.13, so kurtosis cannot separate 'single carrier' from 'noise'; that must come from the spectrum (peak well above the floor, narrow occupied bandwidth) plus a flat envelope. It is also non-monotonic in duty cycle: a 50% on/off signal gives 1.3, 10% duty OOK 7.4, 60 ms/1 s FSK bursts (6%) 17, a 6 ms burst (0.3%) 13. A window-power kurtosis for a CW test reached 984, caused by only the two ramp windows at the edges of a long CW, i.e. extremely fragile to a few outliers (DC spike, drop-outs, edges). Also, kurtosis cannot tell OOK from bursty FSK, because both look the same at burst level. The meaningful split is envelope behaviour INSIDE a burst (constant = FSK/PSK-like, amplitude keyed = OOK/ASK-like). Prefer time-windowed power statistics (robust percentiles, on-time fraction) over a raw 4th moment, and name labels by what is measured, e.g. 'bursty, constant envelope' vs 'bursty, amplitude-keyed', rather than asserting 'OOK' or 'FSK'.

3. SYMBOL-RATE HINT IS THE WEAKEST FEATURE (all from my synthetic experiments). A peak in the FFT of the envelope for random-data 10 kbaud OOK reported 1.29 kHz (peak/median 106), not 10 kHz, because random NRZ has no spectral line at the baud rate. The FFT of the frequency discriminator found 5.0 kHz (baud/2) for iqgen's ALTERNATING-bit FSK only. Shortest-run-length of a thresholded smoothed envelope recovered ~100 us for 10 kbaud random OOK at noise sigma 4 and 12 (amp 40) but failed at sigma 20, and on pure noise it returns a meaningless value. A naive zero-crossing run-length on a lightly smoothed discriminator failed for random 2-FSK even at sigma 4: FSK needs channel filtering and decimation first. RF-Sentinel's own approach (lag-0 cyclic autocorrelation of |x|^2 at a fixed list of 8 candidate rates, then an 'empirical' x2.5 scaling clipped to 1, SDR-BLUE-TEAM.py:951-1012; read-only inspection of an untrusted repo, nothing executed) is envelope-based, so it is blind to constant-envelope FSK, and a fixed rate list can only confirm rates already assumed. Recommendation: v1 reports pulse width in microseconds only for the amplitude-keyed label at high measured SNR, otherwise null; call it 'dominant pulse width', not 'symbol rate'.

4. WRONG CAPTURE WINDOW. The capture happens after the scan cycle (up to scan_seconds, default 600 s, later: cli.py:314-323), for 5 s, only once per signal (cli.py:339,350). Intermittent signals are often simply absent: the result is then 'noise only' or 'unknown', which is absence of evidence, not evidence of absence; README:186 already says such recordings are silent. A different transmitter on the same frequency can be captured instead. The tune centre is a 100 kHz-bin estimate (detect.py:241, cli.py:53) and can be off by tens of kHz. Mitigations: pass duty/hits as a prior; compare in-capture SNR with the sweep's max_snr and flag 'signal_absent'; check the file size against 2*rate*seconds (a short read means dropped data; capture.py:53-55 discards hackrf_transfer's stderr on success, so nothing else reports drops); never characterise an annotation range blindly, the annotation spans the whole file (sigmf.py:77-80).

5. HARDWARE ARTEFACTS MIMICKING STRUCTURE: DC spike (a carrier at the tune centre is ambiguous with it), 8-bit quantisation, saturation harmonics and image/spur products (README:187), filter roll-off and the minimum 1.75 MHz filter, USB drop-outs looking like bursts, uncalibrated gain. Any rule tuned on synthetic ci8 that has none of these will look better than it is. The requested baseband filter is recorded, not the applied one (hackrf_transfer -b rounding is libhackrf behaviour I could not check in this repo).

6. PERFORMANCE AND OPERABILITY. 20 Msps captures are 200 MB (measured via pick_sample_rate) and the web form allows 60 s captures (about 2.4 GB) and 50 per cycle (controller.py:248-249): without a sample cap, inline analysis could stall scanning for tens of minutes; the Pi cost is estimated, not measured. A hard exception in the analyser must not abort the run (hook A try/except). A thread-based variant adds sqlite thread-affinity and shutdown-ordering complexity (store.py:115-118; cli.py:327-334).

7. SCHEMA / DATA HANDLING. No migration exists, so with option (a) every pre-existing scout.db with a captures table crashes the first INSERT with an uncaught sqlite3.OperationalError (cli.py:731-736 only catches RuntimeError). Document it, or add a refuse-with-message guard (not compat code). Relative capture paths (default 'captures', cli.py:623, stored as-is at cli.py:349) make a standalone backfill from another directory fail to find files. Storing the result in both DB and meta creates two sources of truth that can diverge after re-analysis (store analysis_version in both and treat the DB as primary). captures.ts is local-naive while the meta is UTC (cli.py:349 vs sigmf.py:27-30).

8. SCOPE AND DOCS. The README currently makes a hard statement (README:167 'Modulation is not scored ... cannot tell FSK from OOK'); it must change to something precise ('heuristic IQ characterisation; not proof; may return unknown') or it will contradict the feature, and README:186 and :194-196 also need edits. Do not expose a 'confidence' that depends on thresholds that were tuned on the same synthetic generator used in the tests (circular validation); keep thresholds in one named, documented config object (like baseline.BaselineConfig, README:138) and mark them 'starting points, not tuned on real captures'. 'RF-Sentinel-style' features (entropy, cyclostationary, SOM/IsolationForest) are not required for these four labels; adding them raises CPU and explainability cost without evidence of benefit.

9. SECURITY/ROBUSTNESS: the standalone command parses user-supplied JSON/binary files; validate sample_rate > 0 and sane size, ignore unknown keys, and never trust hackrf_scout:signal_id from a file without checking the DB row's frequency. The web server stays read-only and does not start analysis (controller.py:200-202, webapp.py:1-6), so no new attack surface there.

### summary

Audit of RF-SENTINEL-V2 (BSD-3, SDR-BLUE-TEAM.py 3277 lines + rf_sentinel_agents.py) and Substation (AGPL-3.0, substation/*.py), read as data only; none of their code was executed or imported. To test claims I wrote my own numpy re-implementations of each formula and ran synthetic 8-bit HackRF-like IQ (noise sigma ~3 counts per component, fs 2 Msps, N=16384 unless stated). Scripts: /tmp/claude-0/-home-user-hackrf-scout/f99c7e11-f52c-5034-af0a-858cb1074c59/scratchpad/audit/e1_kurtosis.py, e2_cyclo.py, e2b.py, e3*_baud.py, e4_spectral.py, e5_misc.py, e6_sg.py. These are simulations, not real captures, so they show where a formula is mathematically wrong or inert, not how it behaves on real HackRFs.

Headline findings.
(1) Neither repo labels modulation. RF-Sentinel's 'threat_type' is the pre-assigned type of the watchlist channel (SDR-BLUE-TEAM.py:565-583), and its IQ features only drive boolean alert flags and unsupervised anomaly scores. Substation takes modulation from the band config (default 'Unknown'). Neither has PAPR, crest factor, occupied-bandwidth measurement, burst length or duty statistics, chirp/LoRa detection, or a measured symbol rate. RF-Sentinel's bandwidth_hz and duration_ms fields are constants (:1307-1308) and its events table never stores kurtosis or entropy (:1909-1917).
(2) Several RF-Sentinel features do not measure what their names say. 'kurtosis>8' means short-duty bursts, not OOK (balanced OOK has kurtosis ~1). 'cyclostationary_score' / 'swept_alert' is envelope smoothness. The 'advanced CAF' detector is blind to OOK/FSK/GMSK and only sees pulse-shaped PSK/QAM at 8 fixed rates. 'single_carrier' means narrowband, and fires on pure noise as soon as a 1-count DC offset is present. The DTW FHSS score alerts on random walks, ramps and sinusoids.
(3) What is sound and worth borrowing: raw envelope kurtosis as an estimator (with the Rayleigh null 3.245), the null-distribution derivation of the 20x peak/median rule, the ADC-clip fraction, DC removal plus a DC-bin mask, a median-of-gap noise floor, Schmitt-trigger hysteresis, the segment-to-segment power-variance idea as a stationarity measure, the Hampel/MAD outlier filter, and the 'degenerate model' guards.
(4) Hard threshold numbers in both repos (0.55, 0.38, 0.65/0.55, 0.52, 0.35, 8.0, 3 dB, 0.15) are empirical, uncalibrated and tested only on synthetic data. Neither repo has any ground-truth validation.
(5) Licensing: Substation is AGPL-3.0, so borrow ideas only and reimplement; RF-Sentinel is BSD-3-Clause, but its code quality does not justify copying.

### lessons

ADOPT (sound, cheap, numpy-only, reimplement from the idea, since Substation is AGPL-3.0)
1. Every label is a heuristic with a numeric margin and an explicit 'unknown'. Neither repo does this: RF-Sentinel emits booleans and anomaly scores, Substation emits states. Derive thresholds from measured null distributions and unit-test the false-alarm rate across many seeds, as RF-Sentinel did for its 20x peak/median rule (test_sdr_sentinel.py:472-481, a 1e-3 derivation at :706-709).
2. Capture quality flags that cap confidence: ADC clip fraction (|I| or |Q| >= ~122/128 counts; Substation warns above 0.1% and drops at 5%; RF-Sentinel uses >=126 with 2%), DC offset in counts, noise sigma in counts (below ~1 count the envelope is quantised: noise kurtosis 2.55), and a 'noise only / signal absent' check. Any of these should downgrade or produce 'unknown' instead of a confident label.
3. DC handling: mask ~+/-3 bins (or subtract the chunk mean) before every spectral statistic. This single omission makes RF-Sentinel's single_carrier true on 200/200 noise captures with a 1-count DC offset.
4. Noise floor as the median of dB over bins outside the signal (Substation), peak/median detection of narrow lines (RF-Sentinel and mine agree), Schmitt-trigger hysteresis with a hold time for burst slicing, a Hampel/MAD filter on FM discriminator output, and the segment-to-segment power std as a stationarity measure.
5. Persist every raw measure, the method version and the capture conditions (clip fraction, DC, noise sigma, window length); RF-Sentinel's DB drops them, which makes heuristics unauditable.
6. Chunked streaming of the .sigmf-data (Substation reads 4 MB chunks) with online accumulators: running power sums and Chan-merged central moments for envelope kurtosis (sd 0.01 at 1e6 samples), a fixed-bin histogram of the dB envelope for Otsu levels, and a Welch accumulator (K known, so the flatness and entropy nulls exp(psi(K))/K and 0.939..0.9955 can be applied).

ADAPT
1. Envelope kurtosis: report it together with its Rayleigh null (3.245) and use it only as a sparsity measure. Define 'bursty / OOK-like' from the dB-envelope two-level fit instead: Otsu split, level separation d' = (hi-lo)/mean(sd), duty, edge count. Balanced OOK has kurtosis ~1 and 5-30% duty has 1.7-14, so 'kurtosis>8' alone misses most OOK. Note CW/FSK sit at 3.0, DC at 2.9, and clipping flattens the envelope.
2. Narrowband / single carrier: peak/median test with a DC mask, call it 'narrowband', then separate CW / FSK / OOK from the envelope and a discriminator histogram, never from the PSD alone. Prefer more Welch averaging over a Savitzky-Golay filter, and never let an optional dependency change a label.
3. Wideband noise: in-passband spectral flatness plus occupied bandwidth (99% power or -26 dB), both computed over the filter passband only (noise through a 17.5%-wide passband already has entropy 0.745; one empty bin ruins flatness), plus kurtosis ~3.2 and low SNR over the floor. Also report when a capture contains only noise, since the transmitter may not have been active.
4. Symbol-rate hint (label as hint, with confidence): first shift to the spectral centroid / peak and decimate to ~2-4x the occupied bandwidth (Substation's extract-and-decimate idea; implement with numpy FIR/boxcar in chunks), then slice (envelope for OOK, polar discriminator + Hampel for FSK) with a Schmitt trigger, and take the first cluster of the run-length histogram. My toy prototype on synthetic data: 2-FSK 2.4-50 kbaud at 15 dB in-band SNR within 0.4%; OOK 1.2-50 kbaud at >=16 dB within ~1.6%; 0 false estimates in 40 noise runs when requiring d' >= 4.5 (noise gives 2.8 for OOK and 3.5 for FSK); it fails when a carrier offset is left in, and returns 'unknown' at low SNR. This is NOT validated on real captures, ideal NRZ only, and needs a validation harness before shipping. The Substation Gate-1 style segment-power std and RF-Sentinel's pulse-width idea can supply duty and burst-length measures after the same slicing.
5. OOK pulse timing: keep the idea of pulse-width statistics but with percentile levels (not max), hysteresis, a minimum width, correct rise/fall pairing, and a rejection test against the pulse count you would get from noise (hundreds in 16k samples).
6. The 20x peak/median threshold is worth keeping only with the K-dependent null measured for our averaging.

AVOID
1. lag-0 CAF at fixed baud rates (sees only pulse-shaped linear modulation at roll-off >~0.5, 244 Hz resolution), envelope-autocorrelation 'swept' score (envelope smoothness, noise reaches 0.57-0.96 with narrow filters, O(N^2)), DTW/FHSS (alerts on ramps, sinusoids and random walks), GSM FCCH score, non-standard sample entropy, unnormalised STFT entropy, Savitzky-Golay pre-smoothing, the OOK fallback decoder as written, and fake 'fingerprint' fields (cfo_hz = z*100).
2. Any ML scorer built on weak features with rule-generated labels (RF-Sentinel's SOM/Isolation Forest/RF); we have no sklearn and no ground truth. If a learned model is ever added, copy only their guards: refuse if one class >85%, mark degenerate if CV accuracy >0.97 or not above the majority baseline.
3. Constants posing as measurements (bandwidth_hz = sample rate, duration_ms = dwell, 'dBm' from dBFS) and flags named for something else ('single carrier', 'swept', 'cyclo').
4. Substation's audio-domain flatness gates (self-admitted non-working on NFM/SSB) and mean-of-dB channel power as an SNR measure.
5. Single 8 ms snapshots: our 5 s captures allow windowed statistics, but long captures also bring non-stationarity, so compute per-block (0.1-1 ms) series and summarise them; do not take one global moment.

Priority features for the proposal, with a synthetic test-bench built from the nulls above: (a) quality flags and 'unknown'; (b) occupied bandwidth + in-passband flatness -> noise / narrowband / wideband; (c) dB-envelope two-level fit -> constant-envelope vs on-off keyed, with duty, burst count and burst length; (d) a symbol-rate hint from run lengths on the decimated signal for FSK/OOK; (e) SigMF annotations with hackrf_scout: fields holding raw values, method version, confidence and the reasons for any 'unknown'. Every number above comes from synthetic numpy simulations, so real-capture validation (hand-labelled keyfobs, weather sensors, FM carriers, LoRa, noise-only captures) is required before any threshold is trusted.

### substation

Substation (simonholliday/substation, AGPL-3.0) is a multi-channel scanner/recorder for RTL-SDR, HackRF, AirSpy etc. that detects activity on a list of channels and records demodulated audio. It is not a signal characteriser: modulation comes from the band config (substation/band_library.yaml, values like NFM/AM/USB/LSB/TETRA; BandConfig.modulation defaults to 'Unknown', scanner.py:186) and is never inferred from IQ. There is no kurtosis, PAPR, crest factor, occupied-bandwidth measurement, burst-length/duty statistic, baud estimator or chirp detector anywhere in substation/*.py or substation/dsp/*.py ('occupied bandwidth' in config.py:496 is the configured channel width). DCS_BITRATE 134.3 bps is a constant for a known protocol, not an estimate.

IQ and burst handling relevant to us:
- Input: HackRF int8 is scaled by /128 to complex64 (devices/hackrf.py:425-426). File playback reads only 2-channel 16-bit PCM WAV, streamed in 1M-frame chunks with a virtual clock (devices/file.py), so it cannot read ci8/SigMF, but the chunked-streaming pattern is good.
- Per ~200 ms slice (rounded to 131072-sample multiples, config.yaml.default:21-28): saturation test on a ~4096-point subsample (|I| or |Q| > 0.95 of full scale; warn at 0.1%, drop slice at 5%, scanner.py:2094-2119); DC removal by subtracting the slice's complex mean (:2124); Welch PSD with fft_size = slice/8, 50% overlap, Hann, 15 segments, in dB with +1e-12 (:1480-1518); DC bins +/-3 masked (constants.py:113).
- Detection: noise floor = median of dB bins in inter-channel gaps, EMA alpha 0.15, 10 warm-up slices; channel power is the mean of dB over its bins (so it reflects occupancy, not power, as the author says at scanner.py:1738-1742); ON at snr > 4.5-6 dB (3.5-15 by band), OFF at ON minus 3 dB hysteresis, 500 ms hold.
- Burst timing: only coarse. _find_transition_index scans per-segment SNR with hop = fft_size/2 samples (~14 ms at 2.4 Msps) to find where a transmission starts and ends (:1520-1549), then refines on demodulated audio with a 0.02 amplitude threshold and a carrier-click trimmer (recording.py:66-302). Nothing computes or stores burst length, duty or period; bursts shorter than a segment are invisible.
- Noise rejection: Gate 1 (std of channel power across segments >= 3 dB; stationary noise is rejected, but so is any steady carrier, and the null depends strongly on channel bin count: noise passes the gate 59% of the time at 4 bins and under 1% at 12+ bins in my sim) and Gates 2/3b (audio spectral flatness, formula exp(mean log psd)/mean psd, threshold 0.15), which the authors document as not working on NFM/SSB.
- Channel extraction: shift to DC, 5th-order Butterworth low-pass at channel_width/2 with carried filter state, then Butterworth/rational decimation (scanner.py:858-860, :1838-1884; dsp/filters.py). The NFM path adds a polar discriminator angle(x[n]*conj(x[n-1])) and a Hampel (MAD) blanker (dsp/demodulation.py:526-537, :179-249). This is exactly the centre-filter-decimate-discriminate chain our baud/FSK analysis would need, but it relies on scipy, which we cannot use.
- Testing: unit tests use synthetic generators (tests/iq_generators.py: tone, FM, AM, white noise, a bursty FM stand-in); no real-capture validation of any threshold.
- Use: borrow the ideas (clip fraction, DC mask, median-of-gaps floor, Schmitt hysteresis with hold, MAD blanker, extract-then-decimate) and reimplement with numpy; do not copy code (AGPL-3.0). Do not borrow the mean-of-dB SNR, the audio flatness gates or the Gate 1 threshold unmodified.

### snr_definition

snr_db is the IN-BAND, ON-STATE SNR:  snr = P_on / (N0 * B).  N0 = noise PSD (power/Hz) of white complex Gaussian noise that is flat over the WHOLE sampled bandwidth (no anti-alias or baseband-filter roll-off); B = truth['occupied_bw_hz'] (the signal's nominal occupied bandwidth, listed per kind above); P_on = mean signal power over the RF-on intervals only (truth['on_intervals']): gaps between packets/pulses/hops and OOK off-chips do not dilute it, and for hopper it is the power of the one channel active at a time with B the per-hop bandwidth. It is independent of sample rate (a 12.5 kHz NFM at snr_db=12 measures 12.03 dB at 2 Msps and 12.00 dB at 10 Msps) and comparable to a sweep bin power over a signal-sized bandwidth; the wideband SNR over the full sampled band is lower by 10*log10(B/rate). Implementation: noise power per complex sample is 1 (relative), P_on=10^(snr/10)*B/rate, then everything is scaled so the per-component RMS of signal+noise equals rms_lsb, then dc is added, then rounded and clipped to int8 (strong, wideband or very low-duty signals can therefore clip: see truth['clip_fraction'] and truth['warnings']). truth['noise_psd_lsb2_per_hz'] and truth['on_power_lsb2'] give N0 and P_on in LSB units so P_on/(N0*B)=10^(snr/10) exactly. Test: independent Welch estimate from the returned IQ (noise floor = mean PSD of bins outside every band plus a guard; signal = in-band power minus N0*B; divided by on-duty) agrees with the request within 0.39 dB worst case over 23 variants x 3 seeds (typically <0.1 dB); doubling B (occ_bw_hz) at equal snr_db raises measured Psig/N0 by 3.02 dB (expect 3.01); occupied-bandwidth convention is tested (every nominal B holds >=98.7% of the signal power).

### caveats

NOT MODELLED: multipath, fading or shadowing; adjacent-channel interferers, spurs, images, intermodulation; real ADC behaviour (no INL/DNL, only ideal rounding and hard clipping at -128/127; no I/Q gain/phase imbalance; DC is a fixed constant you set, no drift, no LO-leakage-shaped spike); the HackRF baseband filter (noise is white over the entire sampled band, whereas real captures have noise roll-off at ~1.5x signal bw / 1.75 MHz minimum; PSD edges near +-rate/2 will look flatter than real); gain changes/AGC, saturation recovery, burst-edge transients of the real front end; transmitter impairments (PA nonlinearity, frequency drift or chirp during OOK/FSK key-up, crystal tolerance, IQ imbalance; only CW has 5 Hz Lorentzian phase noise and optional linear drift, cfo_hz is a constant); sampling-clock offset (BPSK/QPSK/GFSK-with-integer-sps and OFDM use integer samples per symbol, so symbol_rate is rounded to rate/round(rate/symrate) - OOK/FSK/Gaussian shaping use exact fractional timing); real payload/protocol structure (random bits only: no CRC, whitening, FEC, interleaving, LoRa Gray coding/header, Wi-Fi scrambler or real STF/LTF, real BLE adv addressing; so no protocol lines in the spectrum; the OFDM preamble and LoRa sync/SFD are structurally right but not standard bit-exact); real speech (NFM/AM 'voice' is band-limited Gaussian noise with a ~4 Hz syllable envelope; WFM programme is noise-like music); impulsive/non-Gaussian noise or coloured noise; multiple simultaneous transmitters beyond 'multi' (which sums independent components over one shared noise floor).
CONVENTIONS TO KEEP IN MIND: occupied_bw_hz is a nominal convention that always contains >=98.7% of the power, not the measured 99% bw (NFM uses the 12.5 kHz channel, 99% is really ~7.3 kHz; CW uses a 1 kHz measurement bw; LoRa uses the nominal 125 kHz although 99% is ~136 kHz). SNR is on-state in-band: a bursty signal's capture-averaged power is snr_db + 10*log10(on_fraction) lower and its wideband SNR is lower by 10*log10(B/rate). SNR accuracy is ~0.1 dB (worst 0.4 dB for 0.8*rate-wide OFDM where almost no out-of-band reference exists). Because the capture is scaled to a fixed RMS before int8 rounding, strong or low-duty signals clip (e.g. pulsed duty 1% above ~15 dB, anything above ~30 dB); the generator does not refuse, it records clip_fraction and a warning - pick snr_db/on_fraction accordingly or lower rms_lsb. All signal bands must fit inside +-rate/2 (ValueError otherwise), so keep |offset_hz|+cfo+half-span < rate/2; the hopper span is 5.2*baud (65% of the band at the default baud=rate/8). A capture must be at least one burst long (ook ~56 ms, lora SF7 ~21 ms/SF9 ~83 ms, minimum payload; ofdm/gfsk ~1 ms), and on_fraction windows are never shorter than one burst so the achieved gate may exceed a very small request. 'noise' ignores snr_db and on_fraction. For packet/keyed kinds truth.on_fraction (real on-time) is below gate_fraction. Hop SNR is per hop. Self-test thresholds were tuned against the generator on this machine (numpy 2.5.3, Python 3.13); Python 3.9 / numpy 1.x compatibility is by construction (no new syntax; rng.standard_normal(dtype=float32), np.fft) but was not executed, and bit-exact reproducibility across numpy versions is not guaranteed. Generating 5 s at 10 Msps costs 6-10 s and ~1.2 GB RAM (the iq complex64 return is 400 MB; use return_ci8 plus write_ci8 and drop iq if memory matters). Detector results in meas.envelope_events are for validating the bench, not a proposal for the product feature (its threshold uses the measured noise PSD and on-state power, which a real classifier would have to estimate blindly)).


## Prototype: amplitude statistics

### family

amplitude statistics (envelope / duty / carrier-line features)

### summary

Verdict: envelope statistics are worth shipping, but only after two steps the README idea skips: (1) locate the signal's band and the noise floor from the capture's own PSD, (2) channelise to that band and use the noise floor to compensate the statistics. The RF-Sentinel-style kurtosis of |iq| on the raw wideband capture is nearly blind to the narrowband signals this tool captures: a 12.5 kHz signal in a 2 Msps capture is about 0.6 % of the band, so the raw statistic stays at the noise value 3.24. It cannot see CW, FM, FSK, AM or OOK bursts even at 30 dB in-band SNR.

What works, on seeds 100-119, with DC, CFO and offset in every capture:
- The noise-compensated on-state kurtosis m4_sig gives a stable class value per modulation: constant envelope (CW, FM, FSK, GFSK, LoRa, hopper, LFM pulses, OOK on-chips) 1.00; RRC QPSK 1.20; AM voice 1.26; RRC BPSK 1.37; AM tone 1.76; OFDM 1.99 (noise is 2.00).
- A noise-referenced 2-state Gamma HMM gives duty, burst count and burst lengths; the duty error is below 0.02 down to 0 dB for continuous and packet signals.
- A fine-PSD carrier-line test separates CW from FM/FSK/PSK/OOK (AUC 0.99-1.00) but not from AM.

Corrections to the user's picture:
- QPSK and BPSK with pulse shaping are NOT Gaussian-like (m4_sig 1.20 and 1.37). Only OFDM is (1.99, same as noise).
- 'Wideband noise' cannot be told from the receiver floor by any amplitude statistic. A noise-like emission and the thermal floor both give m4 = 2.00; only a spectral excess over a floor reference can flag it, and a band-filling jammer leaves no reference.
- Envelope kurtosis alone cannot separate OOK from gated FSK/LoRa packets: both have m4_sig = 1.00 in the on-state. OOK is recognised by short, chip-quantised on/off runs (needs about 15 dB in-band SNR to resolve chips).
- A rule-based labeller on these features returns NOISE / CARRIER / CE_CONT / CE_BURSTY / LIN_* / GAUSS_* / PULSED / UNKNOWN with a confidence. Blind results are below.

- The compensation needs the noise floor; a 1 dB error moves m4_sig by -0.23/+0.14 at 4 dB channel SNR.

### results

PROTOCOL
- Thresholds were fixed on seeds 0-9 (tune.jsonl 2780 captures, tune2.jsonl 930, tune3.jsonl 490). All reported numbers are on seeds 100-119, 20 seeds per cell: 25 scenarios x SNR 0/5/10/15/20/30 dB x {native, gated 10/20/30 %} = 5560 captures, with DC +/-8 LSB, CFO +/-5 kHz, offset +/-60 kHz in every capture.
- Noise false-alarm: 400 extra noise captures on seeds 1000-1199 (200 each at 2 and 10 Msps), plus the 40 eval ones. Low-SNR extension: 800 captures on seeds 100-109. Two exploratory runs used tuning-style conditions: OOK/AM/NFM/CW were re-run after the post-eval fix below.
- Chain: pass 1 (PSD, DC, raw moments) -> blind noise floor and band (the sweep prior of centre +/-50 kHz and a bin-quantised bandwidth is used only to pick among PSD clusters or as a fallback) -> channeliser -> tick sums -> presence scan -> HMM -> features -> labeller. The 'oracle' mode (true band and true on-mask) separates feature failure from segmentation failure.
- POST-EVAL FIX (disclosed): on the eval seeds the 'line' channel-narrowing rule (collapse the channel to 8 bins when one PSD cluster holds >=85 % of the excess in 5 coarse bins) wrongly fired on 4/20 Manchester-OOK captures per SNR (m4_sig 1.6-1.9 instead of 1.00) and would have destroyed AM sidebands. I removed it (PSD hull instead), re-ran the six affected scenarios (CW, AM tone/voice, NFM voice, OOK PWM/Manchester) on the same eval seeds, and re-checked them on fresh seeds 200-209: OOK 10 dB -> UNKNOWN, >=15 dB -> CE_BURSTY 100 %, CW 75 % CARRIER / 25 % UNKNOWN, consistent with the corrected eval tables below.

### runtime

All numbers on this x86 Linux box, one thread, numpy 2.5.3, Python 3.13, streaming from a ci8 file in 1M-sample chunks (analyze_file.py, fresh process, VmHWM). 5 s at 10 Msps OFDM-wide (100 MB): 11.5 s total = pass 1 (Hann 50 %-overlap Welch + raw moments) 4.8 s + band finder 0.06 s + pass 2 (FFT overlap-save channeliser, tick sums, fine PSD) 6.0 s + HMM and features 0.7 s; peak RSS 215 MB. 5 s at 4 Msps GFSK (40 MB): 3.7 s, 178 MB. 5 s at 2 Msps NFM / pulsed (20 MB): 2.0-2.5 s, 178 MB. Throughput about 4-10 Msps; 1 s at 2 Msps synthetic captures took 0.4-1.0 s including the oracle pass. Rough Raspberry-Pi-class estimate (5-8x slower): 60-90 s for the 100 MB capture, 10-20 s for 20 MB captures; numpy 1.x upcasts complex64 FFTs to complex128 (about 2x slower and 2x memory), untested here (no Python 3.9 / numpy 1.x installed). Streaming design: (1) pass 1 chunk loop accumulates the Welch PSD, mean, raw moments, clip counter; (2) after the band and noise floor are known, pass 2 re-reads the file, subtracts the capture mean, runs a 64k-point overlap-save FFT channeliser (bin gather = mix + filter + decimate, 25 % overlap, ifftshift to natural order), and accumulates per-tick additive sums (n, sum r, r^2, r^3, r^4, I^4, Q^4, max r^2) and a fine Welch PSD; every statistic (whole capture, on-state, off-state, jackknife) is a sum of ticks, so nothing is held in memory except about 400k ticks x 9 float64 (about 30 MB, ticks capped at 400k: 2.5 us for 1 s captures, about 12-17 us for 5 s); (3) the two-state Viterbi is a pure-python loop over at most 400k ticks (0.4-0.9 s; it is the one non-vectorised piece, and it is done twice). Cost reduction options: non-overlapping Welch (halves pass 1), PSD on every other chunk for stationary signals, skip the fine PSD unless carrier_frac is needed, run the channeliser only on the dominant cluster.

### useless_or_dangerous

USELESS: (1) The central amplitude kurtosis (RF-Sentinel's own definition), raw or channelised: noise 3.246, CE signals 3.0 (AUC 0.50 vs QPSK/BPSK from 15 dB, AM vs OFDM 0.50 from 10 dB), erratic 4-21 for ramps and keyed signals. (2) The raw wideband |iq| kurtosis threshold of 8: blind to every narrowband signal up to 30 dB, and it reads BELOW noise for strong continuous signals (WFM 1.96, LoRa 1.69). (3) I/Q kurtosis and CV: exactly or nearly monotone functions of m4 for these classes (IQK = 1.5 m4, CV not monotone for AM) and neither is noise-compensated. (4) Bimodality coefficient and Otsu eta: AUC 0.6-0.9 at low SNR; Otsu always splits noise (duty 0.56) so it cannot be a presence test; use it only after a presence gate, the HMM duty is better at every SNR below 15 dB. (5) Raw (uncompensated) m4 on the whole capture: it moves with SNR and duty, so there is no threshold; use only the on-state compensated version. (6) The chip-run quality as an 'OOK detector': hopper scores 0.97 and 10 us pulses 0.7 (regular timing, not a keyed carrier). (7) The channel-narrowing 'line' shortcut that I tried first: it collapsed Manchester OOK captures and would remove AM sidebands (removed).

DANGEROUS (looks plausible, is wrong): (a) Unremoved DC/LO leakage: 3 LSB DC fakes a signal band in 100 % of noise captures and a 'carrier'; a real HackRF DC spike is wider and drifts (not modelled), and the capture is centred on the target, exactly where the spike sits. A perfectly stable tone within about 1/T of the tune centre is removed with the DC (over-threshold 2.6 dB, carrier_frac 0.53). (b) Channel mismatch: too narrow (<0.5x the signal) turns FM/FSK into AM (CE reads 2.8-3.4, i.e. 'non-constant envelope'); too wide dilutes channel SNR (m4_sig compensation saves it only if the noise floor is right). (c) Noise-floor bias: the compensation is only as good as N: +/-1 dB gives -0.23/+0.14 at 4 dB channel SNR; real HackRF floors have baseband-filter roll-off, spurs and gain drift (the bench has none). (d) A failed burst mask contaminates the on-state: OOK at 5-10 dB reads m4_sig 1.4-1.9 (looks 'Gaussian-like') with a confident-looking statistic; I added an evidence gate (median on-run >= 12 HMM switch costs), which converts it to UNKNOWN, but the reported confidence in the 0.8-0.95 bin is right only 47 % of the time. (e) Clipping makes strong OFDM look linear (OFDM 1.84 at 6.5 % clip), strong low-duty pulses saturate; reject captures with > 0.1 % clipped samples. (f) AM-style envelopes look like OOK: AM tone at 12-20 dB in channel is shredded into 440-650 'bursts', duty 0.82, labelled LIN_BURSTY (25 % wrong on AM tone) and AM voice gated 6 % read as CE_BURSTY. (g) The label set encodes arbitrary conventions: PULSED = duty <= 6 %, median run <= 100 us, >=5 runs; a short BLE advert (80-128 us) at low duty can be mislabelled; 5 s captures cap the tick at 12-17 us so 10 us pulses get a 2x duty overestimate. (h) The generator is idealised: white Gaussian noise (floor accurate to 0.2 %), no ADC nonlinearity, no AGC, no spurs, no I/Q imbalance, random-bit payloads, constant DC. Real captures will be worse; treat the numbers as upper bounds. (i) Multiple emitters: only the dominant PSD cluster inside the sweep prior window is analysed, a second signal is silently ignored. (j) Synthetic Gaussian-like classes: OFDM and noise cannot be told apart by any amplitude statistic; do not label 'wideband noise' from these features.


## Prototype: spectral shape

### family

spectral shape (Welch PSD, occupied bandwidth, lines, OFDM cyclic-prefix test from the PSD, time-frequency hop test, noise-only test)

### summary

Verdict: spectral-shape cues are cheap (about 4-5 s CPU per 5 s @ 10 Msps capture, about 1 s at 2 Msps, 100-270 MB peak RSS) and, on this synthetic bench, very good at four jobs: (1) telling noise-only from anything with structure, (2) a robust 99 % occupied bandwidth that sorts signals into narrow / medium / wide, (3) a floor-independent OFDM test, and (4) a hopping test with a correct dwell estimate. They cannot see modulation, and they are only as good as three assumptions the bench grants for free: a flat white noise floor, a known baseband-filter roll-off, and no wandering DC. Break any of them and the noise-only test fails badly. With the thresholds frozen on seeds 0-9 and scored on seeds 100-119 (6080 captures, 27 cases, SNR 0..30 dB), clean captures score 99-100 % per class from 5 dB up, noise-only 80/80 (plus 1 false alarm in 440 extra noise captures), 0 OFDM false positives in about 5,700 non-OFDM captures. With 10-30 % on-time plus DC and CFO, accuracy at 5 dB and above is 93-100 % per class (wide 94 %, narrow 93 %) and the usable SNR floor rises by roughly 5-7 dB. These are heuristics, not proof: the label set is {noise-only, carrier, narrow, medium, wide, ofdm, hopper, unknown} and every label carries a heuristic score plus a floor_ok flag.

### results

PROTOCOL. Code and thresholds were developed on seeds 0-9 (3,040 captures: 27 cases x SNR 0,5,10,15,20,30 dB x clean/impaired x 10 seeds). Thresholds were frozen (md5 recorded) and scored once on seeds 100-119 (6,080 captures, 0 errors). Clean = offset +-30 kHz (2 Msps) or +-100 kHz (10 Msps); impaired = DC 6+6j (random sign), CFO +-4 kHz, on-fraction 0.10-0.30. 25 case variants include noise at 2 and 10 Msps, all 15 bench kinds with the self-test variants (AM tone/voice, NFM voice/tone, OOK PWM/Manchester, 2-FSK rect/gauss, LoRa SF7/SF9, OFDM 2/10 Msps and narrow, hopper 2/10 Msps, pulsed, fast pulsed, LFM pulsed, two multi mixes). Grid captures are 1 s at 2 Msps or 0.5 s at 10 Msps (K_eff 115-290); a separate 5 s @ 10 Msps streamed-from-disk check agreed (all 22 labels correct). Pulsed cases clip at high SNR (1 % duty) and are scored as stress. Extra seeds 100-299 were used for noise false alarms, 100-109 for DC/CFO, low SNR, rate sweep and front-end stress, 900-903 for reference widths. The only post-freeze changes (faster Welch segmentation, optional DC guard in the bandwidth sums) are bit-identical for defaults: 0 differences over 40 re-extracted eval captures x 9 features. CAVEAT: the confidence score was redefined after I saw that the first one was uninformative on the eval seeds (accuracy 97 % at conf 0.34-0.67 vs 95 % at conf >= 0.67); the new definition was fitted on tune and replicated on eval (conf >= 0.8: 100 % correct, n = 3715; conf < 0.2: 69 %, n = 330) but eval is no longer blind for confidence only.

### runtime

Measured on a shared 4-core x86 (Python 3.13, numpy 2.5.3) while another job kept every core about 50 % busy (load average 7-8), CPU seconds per capture, single process, 100 MB ci8 streamed from disk in 1M-sample chunks: 5 s @ 10 Msps = pass 1 (read + mean) 0.3 s, pass 2 (Welch nfft 2^15, 50 % overlap, Hann + 100 us spectrogram) 4.3-4.9 s, feature extraction 0.4-0.8 s, total 4.8-5.4 s (about real time), peak RSS 254-277 MB. Without the spectrogram (no hop test): 3.3-3.9 s + 0.1 s, 117 MB. No overlap (K_eff halves, still plenty): 2.6-3.6 s + 0.4-0.7 s, 253-271 MB. Reading only every 4th 1M-sample chunk: 1.3-1.7 s total, 99-106 MB (bursts shorter than a chunk can be missed; it suits steady signals). 5 s @ 2 Msps (10M samples): 0.8-1.0 s total. Full 5 s streamed pipeline measured on 22 captures: 3.5-5.4 s CPU at 10 Msps, 0.8-1.0 s at 2 Msps. Streaming: a 1M-sample chunk is converted to complex64 (8 MB), the Welch carry is nfft/2 samples, accumulators are a 32768-bin float64 PSD and a (frames x 64) float32 spectrogram (about 12.5 MB for 5 s @ 10 Msps); two passes over the file (the first for the DC mean). Welch segmentation was made 15-20 % faster with a contiguous even/odd reshape (bit-identical). A Raspberry Pi-class number was NOT measured: expect roughly 4-8x slower per core (my estimate), i.e. 20-40 s for the full pipeline and 5-10 s with 1-in-4 chunk sub-sampling. numpy float32 FFT is native only from numpy 2.0; on numpy 1.x it upcasts (about 2x time and memory). Python 3.9 / numpy 1.x was not executed; sliding_window_view needs numpy >= 1.20.

The hard-threshold bandwidth sum with isolated-bin cleaning cost me a lot of CW misses before I added the isolated-bin rule.\n\nDANGEROUS (silent wrong answers): (1) The DC mean removal erases a carrier at the tune centre: a CW within about 100 Hz of 0 reads noise-only at any SNR, and the capture is centred on the signal by design. A DC offset and a CW at DC are indistinguishable from one capture; at least report |mean|^2 relative to the floor and treat a large DC with a quiet band as ambiguous. (2) If the tool does not use the baseband_filter_hz it already writes in the meta, edge roll-off makes every capture, noise-only included, look wide (10/10 noise captures called wide); usable_frac = 0.75*filter_hz/rate must come from the meta. (3) A slowly wandering DC or flicker pedestal turns noise-only into narrow (and widens CW) unless the DC guard is a few kHz; the right guard depends on the real receiver and needs a calibration capture. (4) OFDM/LoRa/pulse confusion if the comb test is dropped or the lag range does not cover the symbol time. (5) Duty dilution: a 10-30 % on-time signal needs 5-8 dB more SNR for every feature; a 1 % duty radar is called noise-only or mis-sized below 10-30 dB. Noise-only means 'no persistent structure', not 'nothing transmitted'. (6) A lone line is called carrier but may be the only visible part of an AM voice signal at <= 5 dB (confidence capped at 0.7). (7) carrier_bins is a count of fine bins, so it must scale with the sample rate (or nfft must): at 20 Msps with nfft 2^15 NFM voice is labelled carrier. (8) The synthetic floor is perfectly flat and white; with a 0.5 dB analog floor ripple the sensitivity limits quoted for wideband signals no longer hold, and a signal that fills the usable band simply has no measurable floor and must be answered unknown (OFDM is the exception, via the floor-free CP test)."
